Why token use differs

The differences mostly come from platform context, not from answer length.

Galaxy conditions are much larger than anycode

Galaxy-API code includes Galaxy API interaction, history inspection, job/tool evidence, UDT or tool-selection context, and longer trace reasoning. Open-ended code does local file/code work and avoids that Galaxy evidence chain, so both anycode conditions use more than 80% fewer total tokens than Galaxy-API code with skills.

Galaxy without skills is higher than the base

Galaxy-API code without skills uses 12.3% more total tokens than Galaxy-API code with skills. Almost all of that increase is input context: cached input is 13.3% higher, while uncached input is 7.6% lower and output is essentially flat. The with-skills condition includes `galaxy-token-efficient-operations`, which tells the agent to save bulky Galaxy evidence to trace files and keep transcript output compact. Without that token-saving Galaxy skill, the agent repeats more Galaxy/tool/history context in the conversation.

Open-ended code with skills is still far below the base

Open-ended code with skills uses 81.4% fewer total tokens than the Galaxy base because it does not carry Galaxy histories, API schemas, or tool/job evidence. It is higher than anycode without skills because skills add setup guidance and domain checks, which increase input and reasoning tokens even without Galaxy.

Open-ended code without skills is the smallest

Open-ended code without skills has the lowest token usage: 84.4% below the Galaxy base. It has the shortest context stack: no Galaxy context and no skill instructions. That saves tokens, but the accuracy page shows it also has the lowest accuracy among the four conditions.
