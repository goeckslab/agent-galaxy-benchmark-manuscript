Where the Tokens Go

Two kinds of measurement

Provider usage records give exact billing classes. The event stream shows what the agent did, but it does not label how many input tokens belong to each command, skill, or tool result. This page keeps those measurements separate.

Exact

Total, cached input, uncached input, output, and reasoning output come directly from 150 usage records per condition.

Observed, not billed

Commands, messages, searches, and visible UTF-8 bytes come from the JSONL traces. Bytes are useful for comparing workload, but they are not token counts.

What “unattributed residual” means

It is a limitation of an attribution model, not a provider billing category.

Plain-language definition

We tried estimating repeated context from visible bytes and later agent messages. After subtracting that estimate from exact usage, 33.962% of the Galaxy total remained unexplained. The same method overestimated Open-ended code and produced a negative remainder, proving that old tool output is sometimes truncated, compacted, or omitted. The residual is therefore not used as a cross-condition cost number.

Runtime instructions

System and developer instructions can be supplied on model calls but are not present as ordinary JSONL messages.

Tool definitions

Shell and web tool schemas, argument descriptions, and protocol metadata can occupy context without appearing in command output.

Message framing

Roles, tool-call wrappers, IDs, and other request structure add tokens beyond visible text.

Missing web bodies

The traces record 281 Galaxy search events and 15 Open-ended code search events, but not the complete search-result bodies.

Hidden or compacted state

The runtime may retain, summarize, truncate, or omit prior context in ways the event stream does not expose.

Estimation error

UTF-8 bytes are not tokens, and multiplying text by later messages is only an approximation of context replay.

Interpretation

The reliable comparison is the exact usage and observed loop structure, not the residual estimate.

More loops

Galaxy recorded 2.66 times as many agent messages and 1.90 times as many shell commands.

Larger loops

Cached input per agent message was about 74.6K for Galaxy and 34.0K for Open-ended code, a 2.20x difference.

Answer length is not the driver

Output is less than 1% of total usage in both conditions. Cached input dominates.

Optimization target

Reduce model round trips and keep routine command results compact while preserving full failure diagnostics outside the normal success path.
