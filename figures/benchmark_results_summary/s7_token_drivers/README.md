# Supplementary Figure 7. Where Galaxy runs spent tokens before the interface changes

**a**, Provider-reported token classes for the July 6 BixBench batch, run with GPT-5.5 in Codex after the first prompt and skill revisions and before the Galaxy MCP server changes. Each policy has 150 runs across 50 tasks and three replicates. Dark bar segments represent cached input and light segments combine uncached input and output. The percentages below the bars separate all three classes. **b**, Agent turns are completed agent messages in the event stream, an observable proxy for model calls within a run. Cached input per turn divides cached input tokens by turns. Ratios are those published with unrounded counts. **c**, Each shell command was assigned one primary purpose by the published rule set. Galaxy platform and API commands include history inspection, tool discovery and schemas, job submission, polling and output retrieval. Command counts are not token counts. **d**, The same batch also ran each policy without skill guidance, including the guidance that told agents to save bulky Galaxy responses to files. Labels give total tokens in millions and the percentage of the 150 answers accepted. These are descriptive comparisons within one batch, model and interface version.

The [plotted values](dataset/source_data.csv) keep each published total, per-run mean, share and visible byte count, with its source page. The build checks that class shares sum to 100%, that per-run means equal totals divided by 150 and that cached input per turn equals cached tokens divided by turns. The model is identified from the authors' [token-usage note](../../../supplement/notes/token_usage.md) because the archived pages name only Codex.
