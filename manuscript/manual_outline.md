# Engineering trustworthy AI agents for computational research

## abstract

- Agents can accelerate computational research, but an answer is hard to trust without seeing how it was produced and a clear understanding.
- A MCP interface which connects agents analysis plan to be executed and recorded inside Galaxy workbench.
- Accuracy is kept when using Galaxy to execute models plan; token usage slight higher, but stardard record is kept for every run.

## P1. Agents accelerate computational research, but reviewing what they produce limits trust in thier answers

- Researchers are adopting AI agents quickly as they are proven to plan and execute computational analyses.
- Trust has not kept pace; to some extent the higher production overwhelms the human capability to understand it.
- Agents can be setup to organize the outputs. However, the lack of standartization on how this imposes a challegence fr reproducibility and interpretability.

## P2. Trusting an analysis means trusting both the plan and its execution, and a single benchmark score shows neither

- An agent's knowledge produces a plan; the environment to execute needs to be all built at run time to make it viable. As the analysis grows longer, the chances of errors to occurs grows proportional.
- Benchmarks test planning and execution together. There is a lack of rigorous analysis of the traces generated by the models executing the tasks.
- The understand of where an agent is strong, where it fails, and when to check its answer is fundamental to build trust.

## P3. Galaxy, a workbench built for humans, can be engineered to work with agents

- Galaxy, a world-wide used workbench,  offers thousands of curated tools, compute for large analyses, and histories.
- Galaxy foundation was to humans executing analyses. A Model Context Protocol (MCP) exposes Galaxy's operations to AI agent clients; therefore how agent's interface is designed  changes what the agent achieves.
- We engineered an MCP server and skills and evaluated running three benchmarks. Four models were used to run the tasks three times in two execution environments: custom code and Galaxy. We ask whether the agents and Galaxy combination keeps accuracy, helps on long analyses, and makes agent's variability errors visible enough to judge when an answer can be trusted.

## P4. Agents working through Galaxy scored at least as high as agents writing their own code

- BixBench-Verified-50 89.5% versus 88.3% of answers accepted (difference 1.2 points, 95% interval −1.5 to 4.2); CompBioBench 87.00 versus 86.75 official points, with no paired interval because item-level official grades are not available; multi-step analyses 67.5% versus 58.7% of required results passed (8.8 points, −6.1 to 27.1)
- By model and against other reports: Galaxy scored at or above custom code for three of four models on BixBench and on CompBioBench and for all three on the multi-step analyses, and scores varied more across models (BixBench 83.3% to 93.3%) than between conditions.
- Working through Galaxy did not cost accuracy and incorporated the important features from Galaxy.

## P5. On multi-step analyses, the workbench supplied software that agents writing their own code did not manage to instll and run

- Galaxy runs passed more required results for each of three models, but complete runs were rare in both conditions: 24.4% versus 23.3% (1.1 points, −16.7 to 21.1).
- Galaxy runs passed 70 of 81 results and completed 6 of 9 runs with installed tools, over 6 to 21 hours; custom-code runs passed 7 of 81, completed none and stopped after 10 to 38 minutes, having substituted their own methods, in some runs because a package such as the segmentation model would not install.
- The workbench matters most where an analysis depends on software that is hard to install and run.

## P6. Repeated attempts show that single answers vary, and that a check could recovermost remaining failures
- The consensus, at least two out of three runs correct, recovered more for custom code (0.5 versus 2.2 points on BixBench, 0.9 versus 1.5 on CompBioBench), whose failures were more often isolated to one attempt (groups with exactly two of three passing: 9 versus 16 and 31 versus 43), but not on the multi-step results (69.0% versus 58.1%).
- At least one correct run increases accuracy equally in Galaxy and custom code. Confirming that agent's problem is most often related to execution step and not a knowledge limitation. Also shows the ramdoness on agents execution.
- Answers therefore need a check, and a standard record is what lets a person, or another agent, make it.

## P7. Standard records map agents' errors: interface errors that runs absorbed, and failure causes shared across models

- Among successful runs with event logs, 6% contained at least one recorded execution error.
- In Galaxy these were mostly requests the interface rejected, parameters, and tool lookups, which a better interface can prevent; custom-code runs more often met software that was not available and compute limits.
- Because causes recur across models, fixing them once in the interface serves every model.

## P8. Galaxy costs more tokens, and engieering the interface lowered the overhead

- In the main runs Galaxy used 4.07, 2.48 and 1.47 times the tokens of custom code on BixBench, CompBioBench and the multi-step analyses. Token use did not signal whether an answer was right: a typical incorrect Galaxy run used about as many tokens as a correct one (median 1.85 versus 2.15 million), although a few failing runs used far more (mean 9.0 versus 4.1 million).
- In successive BixBench batches the ratio fell from 5.48 (prompts and skills, GPT-5.5) to 2.81 (MCP execution), and for GPT-5.6 Sol from 3.45 to 2.42 (compact replies) and 1.53 (longer waits), without afffecting the accuracy(137 of 150 answers accepted).
- The token usage reduction is important to not penalize the incorporation of Galaxy features to the task execution pipeline.

## P9. Paired with Galaxy, agent's analyses become inspectable and open to oversight

- AI agents have the potential to automate and accelerate many aspects of computational cancer research; through Galaxy they kept accuracy close to custom code, completed analyses whose software they could not install themselves, and left a standard record of every run, which made their variability and errors identifiable.
- our results show that pairing AI agents with Galaxy enables accurate, verifiable and reproducible computational research, and Galaxy's curated software tools, scalable computing resources and auditable histories support trustworthy AI agents as well as human oversight
